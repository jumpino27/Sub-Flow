### Responsive / drawer behavior added
- **Mobile and tablet (≤ 1179px):** the `.form-panel` is now a fixed off-canvas drawer pinned to the right edge, sliding in via `transform: translateX(100%)` → `0` over 360ms with `--ease-editorial`. Width is `min(440px, 100vw)` so phones get a full-width sheet and tablets get a 440px sheet with the page visible behind a tinted backdrop. Height uses `100dvh` so iOS safe areas/dynamic browser chrome do not clip the footer.
- **Backdrop:** `.drawer-backdrop` is a fixed full-viewport button with a tinted/blurred fill, animated opacity, `pointer-events` gated by the `is-open` class, and `display: none` above 1180px so desktop never paints it. Clicking it calls `closeDrawer`.
- **Sticky drawer footer:** inside the drawer, the form scrolls and `.form-actions` is `position: sticky; bottom: 0` with a top rule and `env(safe-area-inset-bottom)` padding. The submit button stretches with `flex: 1` so it is always the most reachable target; the optional Delete keeps its content width.
- **Drawer entrance fix:** the page-load `rise` animation forces `transform: translateY(0)` on completion which would override the `translateX(100%)` resting state and pull the drawer back on screen. Disabled `rise` on `.form-panel` below 1180px (the slide-in is its own entrance).
- **Close path:** the existing X button in the panel head is upsized to a 40px touch target on mobile, the backdrop closes the drawer, and the existing Esc handler in `page.js` closes it on keyboard.
- **Reduced-motion:** all drawer transitions are stripped under `prefers-reduced-motion: reduce`.
- **Desktop (≥ 1180px):** the form remains inline in the right rail next to the calendar — no drawer, no backdrop. The `drawer-open` class on the rail has no visual effect at that breakpoint.

### Laptop / desktop fit

### Known issues / TODOs for Codex
- The `closeDrawer` helper resets `editingId` and the draft to blank — on desktop this means clicking the X on the form panel clears in-progress edits as well as closing the (always-visible) editor. This matches the prior partial implementation. If Codex wants a softer "clear" vs. "close" distinction on desktop, it can split the X behavior on `min-width: 1180px`.
- `saveItem` keeps the drawer open after a successful create/edit and re-binds to the saved record. On mobile this means the user lands on the just-saved record in edit mode rather than getting an empty state. Intentional, but worth a UX review.
- No focus trap is implemented inside the drawer. Keyboard users can still tab beyond the drawer fields onto the page underneath. Esc + visible close button satisfy the brief, but a real focus trap would be a future polish.
- `body { background-attachment: fixed }` runs four times. Fine on desktop, but iOS Safari can stutter with multi-layer fixed backgrounds — not changed here, flagging only.
